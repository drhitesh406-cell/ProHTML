# Separate HTML Reader test package — subject-wise Marrow Custom Module

This is a separate GitHub Pages test build based on the uploaded `index.html`. It does not modify your original HTML Reader repository.

## Custom Module behaviour

The maker is a step-by-step wizard ending on the **Select tags** screen; the generated test is the final result. The top bar always reads **Create Custom Module** with a ✕ (start over) and the four progress dots, and **< Previous** / **NEXT →** are fixed to the bottom of the viewport on **every** page — long subject, topic and tag lists scroll above them, never behind them, and on the last page **NEXT** builds the test.

1. **Create Custom Module** — choose the number of questions (**10 / 25 / 36 / 40 / 50 / 100**) from a dropdown that always opens downward (it may overlap the module-name field), give the module a name, then **NEXT**.
2. **Select subjects** — **All** or **Choose subjects** (switching to **Choose subjects** unticks everything so you start from none). The 19 subjects appear in the configured order (Anatomy, Biochemistry, Physiology, Pharmacology, Microbiology, Pathology, Community Medicine, Forensic Medicine, Ophthalmology, ENT, Anaesthesia, Dermatology, Psychiatry, Radiology, Medicine, Surgery, Orthopaedics, Paediatrics, Obstetrics & Gynaecology), and each row's **All topics** link jumps straight to that subject's topic screen.
3. **Select topics** — one subject at a time (use the ‹ › arrows to move between selected subjects). Only the **main topics/systems** are listed, each with its **N modules** count. **All** or **Choose topics**; tap **▶** on a system to drill into its individual modules and fine-tune the selection.
   - The grouping is a built-in map of Marrow's main-topic names to the numbered module files of the pinned source; it needs no extra network request. For example Biochemistry shows Carbohydrates (6 modules), Amino acids and proteins (5), Lipids (5), Enzymes and Porphyrins (3), Clinical Biochemistry & Nutrition (4) and Genetics (5); ENT shows Ear (17), Nose (10), Pharynx (6), Larynx (4) and Instruments (1).
   - Selecting a system includes all of its modules. The flat module list is only shown on the drill-down screen, so the topics menu never lists subtopics by default.
4. **Select tags** (last page) — an **All** / **Choose tags** radio and a grid of 16 `#tag` chips. Every fresh maker opens this page with **All** active: **all 16 chips are green** and **Include untagged MCQs** is on, so nothing is filtered out. Tag choices from a previous module are never restored; they last only for the current session. Switching to **Choose tags** unselects every chip and turns the untagged switch off. Clicking any chip while **All** is active immediately switches to **Choose tags** with that chip alone selected; later clicks add or remove individual tags. The untagged tick can still be switched on or off at any time. **NEXT** builds the test.
   - Tags come from `assets/mcq-tags.json`: the 14 non-exam tags are the original pinned Marrow Mini Test evidence (`assets/mcq-minitest-tags.json`), and `#AIIMS` / `#recentNEET` come **only** from QBank Hub's staged Marrow PYQ questions. Tags are joined permanently to **Edition 8 qBank MCQ codes**. The index is embedded into `custom-module.html` as `INLINE_TAG_INDEX` (regenerate with `python3 scripts/embed-mcq-tags.py` after editing the JSON) because the maker runs from a `blob:` URL where a relative `fetch('assets/mcq-tags.json')` cannot resolve — no network request is used for tags.
   - **Exam-only questions are included from Marrow PYQ only.** QBank Hub's staged Marrow PYQs supply every `#AIIMS` / `#recentNEET` question. Those that match an Edition 8 qBank code get the tag permanently; those that do not are kept as **subject-wise, topic-less extras**. An exam extra is added only for a selected subject whose **all topics** are selected — so a specific-topic or mismatched-subject selection never leaks PYQ questions, and a qBank question is never duplicated. FMGE Mini Test files are retained only as tag evidence: **no FMGE question is ever placed in a module**. Mini Test questions that are not in Edition 8 qBank are kept as tag-only sidecar extras, and appear only when all 19 subjects are in scope with their tag selected.
   - **Tag filtering is inclusive everywhere, including questions that are not in qBank.** A PYQ extra carries its full tag list — its exam tag(s) plus any of the 14 Mini Test chips joined by exact question text + options. If it has more than one tag including `#AIIMS` / `#recentNEET`, it still appears when just one of those tags is selected (and under any other tag it carries), and every chip is shown in its explanation. The same `tags.some(...)` rule admits qBank MCQs with extra tags. Selecting several tags is an OR match. The subject/all-topics gate above stays in force independently of tags.
   - **Include untagged MCQs** now admits only questions with no tags at all: a question tagged `#Clinical` is not admitted by a `#AIIMS` selection.
   - Every generated MCQ that has tags shows them as small `#tag` chips at the top of its **Explanation** in the review screen (multiple tags are all shown; untagged MCQs show no chip row, no empty row and no placeholder). The chips are embedded in the generated test at build time, so they need no network at review time.
   - Filtering happens after all source files are read and de-duplicated, before shuffle and the requested question count is sliced. If fewer questions survive the filters than the count you chose, a popup tells you exactly how many were filtered and the test is still built with that many questions (it is never reduced to an error). A zero-match selection shows a popup and builds nothing. The reference runner and MCQ format are unchanged.
5. The reference-format test runner opens immediately and the test is saved in **My HTML → Custom Modules**.

**Full-width maker pages.** On wide screens (iPad/desktop) all four maker pages fill the whole screen: the cyan header, progress strip, white page and footer run edge to edge with no grey side bands. Nothing is stretched — panels, lists and tag chips keep their own widths, and the ✕ / **< Previous** / **NEXT →** controls stay in a centred 900px column.

**Image questions do not blink.** MCQ images are not stored in this repository — only their URLs are (9,500+ point to Marrow's CloudFront CDN), so the first view of an image waits for that download. The runner also rebuilds the whole screen on every option / ☆ / Guess tap, which used to throw the loaded `<img>` away and re-create it empty (the "blink"). The Reader now puts the already-loaded question block back before the browser paints when the content is identical, and reserves each image's space from the size in its CDN file name (`…x1280x1558.JPEG`) so slow images no longer make the page jump. This applies to every reference-format test opened in the Reader, including already-saved custom modules.

Only controls this static reader can actually honour are shown. The pinned source has no difficulty metadata and no Grand Test question store, so those Marrow-app controls are intentionally absent. Bookmarks are a Reader-side feature stored locally on the device, not a source-data field.

## Saved-test rule

When a module is built, its generated reference-runner HTML is saved automatically in:

`My HTML → Custom Modules`

The Custom Module tab changes to a saved-module screen with **Review saved test** and **Delete saved test and unlock maker**. A new custom module cannot be created until that saved test is deleted. It can still be reviewed later and its runner/review state remains on the same device.

## Reader controls

The original Reader library, imports, Favorites, Settings, display modes, Network Access, and offline shell remain available. The Reader's `••• → Font Size` control is a genuine **60%–250% slider**.

On test pages (every library test, custom module, searched MCQ and bookmarked question) the slider raises the **real font-size** of the question stem, option text, option labels, explanations and buttons below them. Each text type keeps its own base size and all scale by the same selected percentage; the page is re-laid-out at the new size, never zoomed or bitmap-scaled, so text stays sharp at every step. The test's top bar (title, counter, timer and close) keeps its normal size.

Every question screen uses the reference (Marrow) layout: the question and its options share one scrollable area — short questions keep the options low on screen, tall content (big images) simply scrolls while the button row stays fixed at the bottom. The MCQ options use white cards with an 88px minimum height (growing as enlarged text requires), no borders, 4px radius and a `0 1px 4px rgba(0,0,0,.1)` shadow, in a two-column grid with a 39px column gap, 10px row gap and 20px page padding on a `#f6f6f6` background; the selected option fills `#c8f3ff` with its option text in `#777777` (the A) B) C) D) labels keep their own grey). Question stems are **20px / 700 / `#7B8085`**. Option text is **16px / `#111111`**, at weight **500** while attempting and **400** in review, with **11px / 400 / `#AAAAAA`** labels while attempting (in review the label matches its text). Explanation body text is **16px / 400 / `#555555`**, and bold explanation terms are **16px / 700 / `#333333`**. Question content retains the existing bundled **Inter** typeface and system-font behavior, with the original Inter 400/700 files in `assets/fonts/` cached offline. Question images are centred on screen. The test name is hidden on question screens (it stays on the start and score screens), and single-section tests show just the "question of total" counter in the taskbar instead of the "Full test" chip. In review, every skipped question shows a "You skipped this question" line in red below its options; answered questions show nothing extra. Section programming is exactly as in the original test files: Next is simply disabled at a section's last question, nothing advances while the app is closed, and the End-section button — normally out of the bar — automatically appears only at the last question of a section, and only in tests with more than one section (the final section's last question says **SUBMIT** instead, with confirmation). The bottom bar carries ☰ (all questions), ☆ (mark for review), a Guess checkbox, then PREV and SKIP/NEXT pushed to the far right of the bar — all in one 44px row sharing the same baseline. The SKIP/NEXT/SUBMIT button keeps one constant width with its label centred, so nothing in the row shifts when the label changes. Tapping a selected option clears it; tapping a different one switches your choice; answering never scrolls the page away from the option you tapped. The section clock keeps running while the app is closed: if a section's time already ended in the background, the test reopens at the section that should be running now (or submits itself when everything expired). Answering a searched MCQ keeps the same screen for 0.80 s while the option boxes change colour (chosen wrong option salmon `#da8b7e` with white text, correct option light green `#caed93` with muted text), then the options fade out and the review fades in over 0.50 s. The question block is never part of that transition, so its text does not move, resize or change colour; the review (plain option rows, white strip, explanation) then flows directly beneath it, like the review screen of a full test. A remembered answer restored on opening goes straight to the review, and **Try again** returns to the unanswered layout for the next attempt. The thin line under the test header bar is removed on every test page. Review screens use the Marrow layout — full width with no card box, the cyan Q MCQID pill, plain single-column option rows (no cards, no percentages: the correct row is green with a round tick, your wrong choice has a round ✗, everything else is unchanged), then a full-width white strip, the tag chips with the bookmark button on the grey page background directly under it, and the explanation text without any white box, plus PREV / NEXT / ☰ / DONE — and each question scrolls in its own page box, so **Next** and **Prev** always open the next question at the top.
**Case data under the question.** Lab values, bullet points, numbered lists, 3–4 line `1. 2. 3.` blocks and tables (the source's `question-desc-html` block) are body text, not a second stem: **16px / 400 / `#4A4A4A`**, scaled by the font slider like every other text, with bold terms and table headings kept bold. The stem sentence above them stays 20px / 700 / `#7B8085`. The source's dead "Expand Table" button is hidden (nothing in the app handles it and tables already show in full).

**One Marrow UI everywhere.** The start page, question palette, end-test dialog, results page and review screens use the same Marrow tokens as the question and custom-module filter screens: the template's cyan pair is remapped to the Marrow cyan (`#70d0e0` / `#1f95ad`), main actions are the cyan pill, secondary buttons the light-blue Previous pill, selected chips/pills the light-cyan `#c8f3ff` state, cards white with the soft option-box shadow, and page titles the 16px/700 ink title used on the review screen.

## Fully embedded, offline Marrow data

`custom-module.html` carries its entire source pool inline as a deterministic gzip + base64 blob (`EMBEDDED_DATA_B64`) plus a small `EMBEDDED_MANIFEST`. At boot the maker decodes it in the browser with `DecompressionStream('gzip')`; `sourceFetch()` reads topic files from that decoded object. **Building a module uses zero network requests** — there are no `TAGS_URL`, manifest or topic-file fetches, and no network fallback. If decoding fails on an old browser, the maker reports it instead of silently going online.

The pinned sources are WEBREPLITX5 `7442d6f9…` (Edition 8 qBank and NEET-PG Mini/Test/Subject series) and QBank Hub's staged Marrow PYQ artifact. At generation time:

- 829 Edition 8 qBank topic files / 16,376 MCQs form the only base pool for whole modules and untagged MCQs;
- 2,678 qBank codes get permanent tags (3,018 assignments);
- 872 NEET-PG Mini Test tag-only extras and 4,391 QBH PYQ extras are stored as sidecars. A deterministic classifier (`scripts/classify-mcq-tags.py`) now gives every one of them a **subject and a module topic** and extends the 13 non-exam tags over the whole pool (see below);
- image questions keep **URL fields only** — no downloads, no base64 image bytes, no increase in repository size. `<img>` tags are created from those URLs at render time with `loading="lazy"` and `referrerpolicy="no-referrer"`; with Network Access OFF the reader's CSP still blocks remote images while all text, options, answers and explanations stay intact.

Regenerate deterministically with:

```
python3 scripts/build-custom-module-data.py --web5-tar /tmp/web5.tar.gz \
  --qbh-gz /tmp/qbh/import-reports__marrow-pyq-stage-v1.json.gz
python3 scripts/embed-mcq-tags.py
```

The generator writes `assets/mcq-tags.json`, `assets/mcq-question-index.json` and `assets/custom-module-data-manifest.json`, then replaces only the marked embedded-data blocks in `custom-module.html`: a 34 KB manifest in the main script and the gzip payload as a non-executing `<script id="cm-embedded-data" type="text/plain">`. It is idempotent (gzip `mtime=0`, sorted keys). `REFERENCE_TEMPLATE_B64` — the reference MCQ runner — is never rewritten.

**Bookmarks.** A bookmark button sits beside the MCQ-code search button in the library filter row, with a live count badge. Opening it shows a full-screen **Bookmarks** page that lists each subject with its saved-question count; tapping a subject opens a separate full-screen page containing only that subject’s MCQs, with a **‹ Back** button to the subject list. This replaces the old anchored dropdown/accordion. In review screens the bookmark icon stays in the explanation: at the right-hand end of the tag-chip row when tag chips are present, otherwise on a right-aligned line at the start of the explanation box (and in `#explanation` for code-searched MCQs). It is never placed in the question-number row. Clicking it turns the Reader theme blue (`#2d6ae3`). Bookmarks are stored in `localStorage` under `htmlReader.bookmarks.v1` as full question snapshots, grouped only by the subject shown in that review section. Keywords are used **only** when that subject is undecided or unclassified. Opening a bookmark from a subject page uses the single-MCQ reader; **Try again** and **Next** appear together only after an option is chosen and the explanation is revealed — even when that question has a remembered answer on the device. **Next** advances through that subject’s bookmarks in the listed order and, after the last one, returns to that subject’s bookmark page. Bookmarks survive deleting the custom module or source file they came from.

**Completed-test badge.** When a local test is finished, the green badge in the library row now reports question accuracy instead of marks: the large number is the **rounded percentage of correctly answered questions** out of all questions in the test, and the small line is **`correct / total` questions** (with `· N tests` when one HTML file contains several finished tests). Negative marking and NEET-PG/INI-CET mark weights no longer affect this badge. The full in-test score summary still shows marks and is unchanged.

**Maker startup.** The 15 MB `custom-module.html` no longer makes the JS engine parse 14.7 MB of base64 string literals just to show the wizard. The gzip payload is raw, non-executing text; boot reads only the 34 KB `EMBEDDED_MANIFEST` and decompresses the 48.7 MB JSON once in an idle callback or on the first **Build**. HTML Reader caches the maker Blob, prefers the service-worker shell cache, and opens that Blob directly — no second 15 MB text decode, full-page regex scans, head injection or duplicate Blob. The maker carries its own offline CSP, so opening and building still need zero network requests.

**MCQ-code index.** `assets/mcq-question-index.json` now contains every `M[A-Z]\d{4}` code found in the pinned qBank, Marrow PYQs and the non-FMGE NEET-PG Test/Subject/Mini series (43,179 codes / 1,718 topic rows). The earlier 24,894 figure covered only qBank + Mini Tests + WBX PYQ + QBH PYQ; a full pass over all NEET-PG series found the rest. These series-only codes are resolvable by MCQ-code search only — they are never inserted into a module pool unless already eligible as a tag-only extra.

## Deploy safely to a new repository

1. Create a new empty public GitHub repository, for example `html-reader-subjectwise-module-test`.
2. Extract the ZIP and upload the **contents** of this directory to the new repository's `main` branch root. Do not upload the enclosing directory as a nested folder.
3. Go to **Settings → Pages** and set:
   - Source: **Deploy from a branch**
   - Branch: **main**
   - Folder: `/(root)`
4. Open the published Pages URL. In the Reader, enable **Settings → Network access** and test the Custom Module tab.

## AI-assisted tag and topic classification

The 13 non-exam tags used to come only from Mini Test *filenames* joined to qBank codes, so a tag pool was small and had **no subject or topic** — asking for `#Clinical` in Medicine returned nothing. `scripts/classify-mcq-tags.py` closes that gap with rules only (no model, no API key, no network):

- **Subject + topic for every extra.** Each tag-only Mini Test extra and each PYQ extra is matched by nearest neighbour against the Edition 8 qBank corpus (token overlap, the same idea the data generator already uses) and falls back to a subject profile when the topic is unclear. Measured leave-one-out accuracy on qBank questions: **~88% subject, ~88% topic**; topic assigned to ~94% of extras.
- **The 13 non-exam tags over the whole pool.** `#Clinical`, `#Slides`, `#Numbers`, `#Problems`, `#Eponyms`, `#TheCommons`, `#Instruments`, `#Criteria`, `#Drug_OfChoice`, `#Investigation_ofChoice`, `#Controversial` and `#ImageBased` are assigned from question text and images. `#GIFBased` is set when the image URL is a GIF. `#ImageBased`/`#GIFBased` are objective (an image is present / it is a GIF), never a judgement call. Rules are matched against the **question stem only**, never the explanation: a tag describes what the question asks, so a Cardiology stem whose explanation happens to say "drug of choice" is not tagged `#Drug_Of_Choice`. `#Slides` additionally requires an image to be present. `#Clinical` marks a **vignette**, and needs both a **patient anchor** (an age or age band such as "58-year-old"/"middle-aged", or a person noun such as "man"/"patient"/"primigravida") **and case evidence** (a narrative verb such as "presents"/"complains"/"underwent"/"you notice", or a measured value such as "122 mg/dl" or "BP 90/60"). The earlier rule fired on a patient noun alone, which swept in one- and two-line fact questions phrased "in a patient with X"; that pattern is now untagged. Marrow's Mini Test tags are a single dominant label per question, so a vignette tagged `#Drug_Of_Choice` is still a vignette - `#Clinical` here is additive, not exclusive. This rule was calibrated against 36 Marrow-labelled questions (28 `#Clinical`, 8 untagged): it reproduces all 36, where the previous rule mis-tagged every untagged one.
- **Exam-history tags are never touched.** `#recentNEET`, `#AIIMS` and `#RecentUpdates` record what was actually asked; the classifier neither adds nor removes them. `#recentNEET`/`#AIIMS` still come only from QBank Hub PYQ.
- **Nothing is replaced.** New tags are unioned with the existing Mini Test tags, so the old counts stay a subset. A question may end up with no tag or several tags; both are fine.
- **One row per question.** The same question can sit in Edition 8 qBank, a Mini Test and a PYQ paper at once (different HTML, entities or spacing). The maker and the classifier both collapse those copies by normalised text + sorted options, keep the qBank copy, and union the copies' tags, so a built module never repeats a question and no tag is lost. A PYQ copy that duplicates a qBank question is removed but its tags are folded onto the survivor first. Across all sources: 21,639 raw records become **21,511 distinct questions**, and exactly one copy of every duplicate survives.
- **Topic-aware extras.** In the maker, a tagged extra now appears for its own subject **and topic** (not only when all 19 subjects are selected). Extras the classifier could not place keep the old all-subjects rule, and a PYQ extra without a topic keeps the old subject + all-topics rule, so nothing is ever mis-filed. Exam tags (`#AIIMS`/`#recentNEET`) behave exactly as before.

Outputs: `assets/mcq-ai-tags.json` (the overlay), the extended `assets/mcq-tags.json`, the patched embedded payload (extras gain `_subject`/`_topic` and unioned `_tags`) and a regenerated `INLINE_TAG_INDEX`. Re-run any time with:

```
python3 scripts/classify-mcq-tags.py            # apply
python3 scripts/classify-mcq-tags.py --dry-run  # report only, write nothing
```

## Main files

- `index.html` — Reader with Custom Module tab, Bookmarks pages, persistent saved-module handling, and font-size slider
- `custom-module.html` — step-by-step Marrow-style maker with main-topic/system grouping, module drill-down, last-page tag filter, subject-gated Marrow PYQ extras and reference-runner conversion; carries the whole source pool inline
- `assets/bookmarks.js` — shared bookmark store, full-screen per-subject pages, and the standalone runtime injected into every MCQ frame
- `assets/mcq-tags.json` — canonical static qBank-code → tag index (Mini Test pin + rule-based AI tags)
- `assets/mcq-ai-tags.json` — deterministic rule overlay: qBank tags, extra subject/topic, extra tags
- `scripts/classify-mcq-tags.py` — offline rule classifier for tags and extra subject/topic
- `assets/mcq-minitest-tags.json` — immutable Mini Test tag evidence used by the generator
- `assets/custom-module-data-manifest.json` — reproducible counts/rules for the embedded pool
- `scripts/build-custom-module-data.py` — deterministic generator for the embedded pool, tag index and code index
- `scripts/embed-mcq-tags.py` — embeds the tag index into `custom-module.html` for blob-URL use
- `docs/qbank-hub-module-migration.md` — **planned, not active** QBank Hub data-source migration: inventory, per-subject/per-tag counts, pros/cons and switch steps
- `scripts/build-qbank-hub-module.py` and `assets/qbank-hub-module-counts.json` — checksum-verified staging generator and its reproducible counts artifact for that plan. The maker still uses the pinned Marrow source.
- `sw.js` — PWA service worker
- `manifest.webmanifest`, icons, `.nojekyll` — GitHub Pages/PWA support

## Question typography regression test

With the static server running on port 3000 and Playwright installed, run `node tests/question-typography.cjs`. It uses the actual embedded reference runner to verify local HTML tests and saved custom modules, then checks the shared searched/bookmarked MCQ view. Assertions cover computed font sizes, weights, colors, surfaces, nested rich text, explanation bold terms, proportional 150%/175% resizing without zoom, and option-card growth. `BASE_URL`, `PLAYWRIGHT_MODULE`, `PLAYWRIGHT_CHROMIUM_EXECUTABLE` and `QA_DIR` can override the defaults.
